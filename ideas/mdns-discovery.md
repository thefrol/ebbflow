# mDNS Discovery — обнаружение ламп в LAN и переключение между ними

Готовая спека для реализации. Статус: **реализовано**.
Берёт на себя «обнаружение в LAN» из roadmap v3 (`ideas/future.md`).

## Цель

В веб-интерфейсе лампы появляется блок «Другие лампы»: список таких же
устройств в локальной сети со ссылками — кликнул и перешёл на веб соседа.
Обнаружение автоматическое, без сканирования подсети и без ручной
конфигурации. Заодно у лампы появляется осмысленный локальный домен
(`<имя>.local`) и возможность переименовать устройство без перепрошивки.

## Дизайн

**Протокол — mDNS** (компонент `espressif/mdns`; с ESP-IDF v5.0 он вынесен
из ядра, подключается `idf.py add-dependency espressif/mdns`).

Разделение ролей: **mDNS = обнаружение и визитка, HTTP = подробности**.

1. Каждая лампа анонсирует сервис `_ebbflow._tcp.local`, порт 80, с
   TXT-записями-«визиткой»:
   - `id` — уникальный ID устройства: MAC от `esp_read_mac()` в hex
     (естественный первичный ключ флота);
   - `ver` — версия прошивки (`esp_app_get_description()->version`);
   - `chip` — `CONFIG_IDF_TARGET`;
   - `mode` — текущий режим (`schedule`/`pulse`).
   TXT — маленькие строки, суммарно сотни байт; не класть туда ничего
   лишнего. Полная информация о соседе дотягивается HTTP-запросом к его
   `GET /api/info` (уже есть, задел под флот).
2. Hostname лампы = имя устройства (см. шаг 2 реализации): лампа отзывается
   на `<имя>.local`. Опционально поверх — алиасы через
   `mdns_delegate_hostname_add()` (например `greenhouse.local`), в первой
   версии можно пропустить.
3. Лампа, к которой подключился браузер, сама делает browse сети
   (`mdns_query_ptr("_ebbflow", "_tcp", ...)`), собирает список соседей
   и отдаёт его новым эндпоинтом `GET /api/peers`.
4. Веб-страничка рисует список со ссылками `http://<host>.local/`
   (fallback на `http://<ip>/`, если hostname не резолвится с клиента).

Граничные случаи, которые надо переживать молча:

- роутер фильтрует multicast → соседей не видно: показываем пустой список,
  это норма, не ошибка;
- свой собственный анонс прилетает в browse → отфильтровывать по своему
  `id`/hostname;
- browse блокирующий — делать с таймаутом (~2–3 с), не в задаче httpd без
  нужды; результат разумно кэшировать на ~30–60 с, чтобы каждый рендер
  страницы не гонял multicast;
- mDNS стартует только после `IP_EVENT_STA_GOT_IP`, до Wi-Fi его нет.

## Что уже есть в коде (точки опоры)

- hostname DHCP = `CONFIG_LAMP_DEVICE_NAME` — `main/wifi_setup.c:38`;
- `GET /api/info` (name/version/chip) — `main/web_server.c:89`;
- регистрация роутов httpd — `main/web_server.c:336`;
- настройки NVS + Kconfig-дефолты — `main/settings.*`,
  `main/Kconfig.projbuild` (новые настройки добавляем и туда, и туда);
- запасной вариант с компьютера — `tools/scan.sh` (остаётся, mDNS его
  не заменяет: сканер работает и там, где multicast зафильтрован).

## Шаги реализации

1. **Зависимость.** `idf.py add-dependency espressif/mdns` (попадёт в
   `main/idf_component.yml` + `dependencies.lock`). Собрать под обе цели
   (`esp32c3`, `esp32c6`) — конвенция репозитория.
2. **Имя устройства в NVS.** Сейчас имя — только `CONFIG_LAMP_DEVICE_NAME`.
   По конвенции «Kconfig = дефолты первого запуска, NVS = живые настройки»
   добавить строковую настройку `name` в `settings_*` (Kconfig-дефолт тот
   же), использовать её в: `esp_netif_set_hostname` (`wifi_setup.c`),
   mDNS hostname, `GET /api/info`. Добавить поле в `GET/POST /api/settings`
   и в форму веба — переименование без перепрошивки.
3. **Новый модуль `main/mdns_discovery.[ch]`.** Функция
   `mdns_discovery_init()` (вызывается из `app_main` после Wi-Fi):
   `mdns_init()` → `mdns_hostname_set(name)` →
   `mdns_instance_name_set(name)` → `mdns_service_add(NULL, "_ebbflow",
   "_tcp", 80, txt_items, n)` с TXT-визиткой из шага дизайна.
   Функция `mdns_discovery_browse(peers, max)` — обёртка над
   `mdns_query_ptr` с таймаутом и разбором `mdns_result_t` (hostname,
   адреса, порт, TXT). Логи по-русски, тег `mdns`.
4. **`GET /api/peers` в `web_server.c`.** JSON-массив
   `[{id, name, host, ip, port, version, chip, mode}]`. Источник —
   `mdns_discovery_browse` + при желании дотягивание `/api/info` соседа
   (в первой версии достаточно данных из browse + TXT). Не забыть про
   лимит URI/буферов httpd по аналогии с существующими хендлерами.
5. **Веб-страничка `main/web/index.html`.** Блок «Другие лампы»:
   `fetch('/api/peers')` → список ссылок `http://<host>.local/`
   (fallback на IP). Состояния: «поиск…», «никого не найдено».
   Vanilla JS + fetch, как сейчас, без новых зависимостей.
6. **Сборка и проверка.** `idf.py build` под обе цели. На компьютере:
   `dns-sd -B _ebbflow._tcp` (macOS) или `avahi-browse -rt _ebbflow._tcp`
   — лампа видна с TXT. С двумя прошитыми устройствами: каждая видит
   соседа в `/api/peers` и в вебе, переименование через веб меняет
   `<имя>.local` после перезагрузки.
7. **Релиз.** Обычный путь: тег `v*` → CI → OTA (скилл
   `.agents/skills/firmware-release`). Учесть: обновлённые лампы увидят
   только таких же обновлённых — старые прошивки сервис не анонсируют.

## Не входит (out of scope)

- MQTT / центральный контроллер флота (это v3 из `future.md`, отдельная
  история — mDNS-discovery её не отменяет);
- delegated hostname-алиасы (можно добавить позже одним вызовом);
- host-тесты: модуль завязан на сетевой стек ESP-IDF, чистой логики для
  `test/` тут почти нет (разве что разбор TXT — если выделится в чистую
  функцию, покрыть по конвенции репозитория).
